# ragwrench bm25

Whitespace-based BM25 tokenizers find almost nothing in Chinese or Japanese text, which
has no spaces between words. `ragwrench bm25` builds CJK-aware BM25 sparse vectors
(character bigrams, or optional jieba) and indexes and searches them with Qdrant local
mode, fully offline. Use it for keyword or hybrid search over Chinese, Japanese, Korean or
mixed-script documents without a server or a model download.

_Formerly the standalone `qdrant-bm25-cjk` tool (`qbm25`)._

Offline BM25 keyword search for Chinese, Japanese, Korean and mixed-script text.
Encode text into stable sparse vectors, index JSONL with Qdrant **local mode**,
and search without a server, API key, FastEmbed, model download or mandatory NLP
library. The standalone Python encoder uses only the standard library; the CLI's
Qdrant dependency brings NumPy and other client dependencies.

## Quick start

Needs the `qdrant` extra.

```sh
pip install 'ragwrench[qdrant]'
ragwrench bm25 index --path .artifacts/qd --collection kb examples/bm25/corpus_zh.jsonl --tokenizer cjk-bigram
ragwrench bm25 search --path .artifacts/qd --collection kb '向量数据库 备份' --top-k 3
ragwrench bm25 encode 'Qdrant向量数据库' --document --avgdl 5
```

Run index once with a fresh collection name. Repeating it intentionally fails;
use `update` for add/delete batches or create a different collection to rebuild.
The store persists across processes.
The first search result in this example is `d1`, the snapshot/backup document.

Input is UTF-8 JSONL, one object per nonblank line:

```json
{"id":"d1","text":"Qdrant 向量数据库支持快照备份与恢复。","metadata":{"topic":"backup"}}
```

`id` and `text` are required; `metadata` is an optional JSON object. IDs can be
nonempty strings (<=256 characters) or unsigned 64-bit integers. Duplicate IDs,
unknown top-level fields, duplicate JSON keys, NaN/Infinity and invalid records
are rejected before collection creation. Integer `7` and string `"7"` remain
distinct; deterministic UUIDv5 point IDs preserve the original source ID in the
payload. Metadata is stored as data, never evaluated.

Search writes a JSON array to stdout, with objects containing `id`, numeric
`score`, `text` and `metadata`. Index writes a JSON build report including config,
indexed/skipped counts and collision statistics. Encode writes `tokens`, sorted
`indices`, corresponding `values`, config and collision statistics. Diagnostics
and empty-text warnings go to stderr; errors exit 2. No matches return `[]`.

## Encode with a saved config, offline

`encode --encoder-config FILE` uses one caller-saved compatible **Encoder.config
object** and one text, with optional `--document`. For a standalone example:

```sh
mkdir -p .artifacts
python - <<'PYCONFIG'
import json
from pathlib import Path
from ragwrench.bm25 import Encoder
config = Encoder("whitespace", k1=2, b=1, avgdl=4, stopwords=("atlas",)).config
Path(".artifacts/offline-encoder.json").write_text(
    json.dumps(config, ensure_ascii=False), encoding="utf-8"
)
PYCONFIG
ragwrench bm25 encode --encoder-config .artifacts/offline-encoder.json 'ＡＴＬＡＳ 北京 北京 東京 서울 é'
ragwrench bm25 encode --encoder-config .artifacts/offline-encoder.json 'ＡＴＬＡＳ 北京 北京 東京 서울 é' --document
```

Both return the usual `tokens`, sorted `indices`, corresponding `values`,
`config` and `collision_stats` JSON. The example's tokens are
`["北京", "北京", "東京", "서울", "é"]`; query weights are all `1.0`.
Document weights are `4/3` for `北京` and `6/7` for each other token, using the
saved `k1=2`, `b=1`, `avgdl=4`. The returned compatible config is preserved;
finite JSON integer or float BM25 parameters are canonicalized to floats.

The file uses the same strict **1 MiB** UTF-8 format and runtime validation as
[index with a saved config](#reindex-with-a-saved-encoder-config): exactly an
`Encoder.config` object, with normalized/sorted/unique stopwords. Whole wrappers,
duplicate keys, missing/extra fields, nonfinite or overflowing numbers, malformed
Unicode and incompatible versions fail before encoding. Any combination with
individual `--tokenizer`, `--stopwords`, `--k1`, `--b` or `--avgdl` flags is an
error, even for equal values; conflicts are rejected before reading files.
Errors exit 2 with stderr diagnostics and no JSON. The existing 1,000,000-character
text limit, empty/stopword-only warnings and hash-collision diagnostics remain.
Empty or stopword-only input returns empty token/index/value arrays.

No collection, corpus or original store is accepted or accessed. Query weights
remain unique-dimension ones; document weights contain TF only, with no IDF.
This does not export config, authenticate sources or establish collection score
parity. Optional jieba still requires its extra and may use its dictionary cache.
Without the file, ordinary encode defaults (`avgdl=100`) and individual flags
remain available.

### Encode one text file

Use `--text-file FILE` instead of the positional text to avoid platform argv
size limits. It accepts exactly one UTF-8 text file, with either individual
config flags or `--encoder-config`, and optional `--document`:

```sh
printf 'ＡＴＬＡＳ 北京 北京\n東京\t서울 é\n' > .artifacts/offline-text.txt
ragwrench bm25 encode --text-file .artifacts/offline-text.txt --encoder-config .artifacts/offline-encoder.json
ragwrench bm25 encode --text-file .artifacts/offline-text.txt --encoder-config .artifacts/offline-encoder.json --document
```

These return the same JSON and weights as the saved-config example above.
Exactly one of positional text (including `''`) or `--text-file` is required;
both/neither fail before any file access. Config/individual-flag conflicts also
fail before file reads. Ordinary positional text and defaults remain supported.

The binary read is bounded to **4 MiB plus one overflow-detection byte**; files
over 4 MiB are rejected. Decoding is strict UTF-8, with no newline conversion,
whitespace stripping or BOM removal: a leading UTF-8 BOM becomes literal U+FEFF
and is processed by the selected tokenizer like positional text. The decoded
text must also fit the existing **1,000,000-character** limit before encoding.
Missing/unreadable files, invalid UTF-8 and either size violation exit 2 with
stderr diagnostics and no JSON. Empty/whitespace-only/stopword-only files retain
the normal empty-vector warning; collision diagnostics are unchanged.

This is one text, not a JSONL corpus or batch. `-` is a literal filename, not
stdin. Encode does not access a collection, apply IDF or write an output file;
it prints the usual JSON to stdout. The input/config files are read only.

## Explain a query's score

```sh
ragwrench bm25 index --path .artifacts/explain-qd --collection kb examples/bm25/explain-corpus.jsonl
ragwrench bm25 search --path .artifacts/explain-qd --collection kb 'ＢＥＩＪＩＮＧ 北京 北京' --explain
```

`--explain` returns an object with `schema: 1`, the saved encoder `config`,
`corpus.document_count`, `query` and `results`. Without the flag, search still
returns its usual JSON array. The example's normalized, post-stopword query
tokens are `["beijing", "北京", "北京"]`, with term frequencies
`{"beijing": 1, "北京": 2}`. Results are integer `7` then string `"7"`, with
scores approximately `0.598186` and `0.420817`; the original text and metadata
remain paired with each typed ID. `beijing` has document frequency zero and
contributes zero. `北京` has document frequency two and IDF `ln(1.6)`;
repeating it does not increase its query weight above 1.

`query.dimensions` lists each hashed index, its normalized query tokens,
query weight, live document frequency and IDF. Each result's `explanation`
lists normalized document tokens, term frequencies, document length, and
per-dimension TF weights and IDF contributions. Matching `document_terms`
show each token's raw frequency and TF weight. Colliding tokens share one
dimension: document TF weights merge, query weight stays 1, and IDF counts
documents containing that dimension. A false match caused by a hash collision
therefore shows the actual contributing document token, even when the query
token itself is absent.

Explanations preserve Qdrant's result order, cutoff choices and numeric `score`.
`score_sum` sums contributions using the stored vector weights;
`score_delta = score_sum - score` exposes the difference from Qdrant's float32
score rounding. Regression fixtures check agreement within 1e-6 absolute error;
this is a numeric tolerance, not a relevance or performance claim.

Inspect a source document even when it is outside top-k or does not match:

```sh
# JSON integer 7 versus JSON string "7" (keep the inner double quotes):
ragwrench bm25 search --path .artifacts/explain-qd --collection kb '北京' --top-k 1 --explain-id 7
ragwrench bm25 search --path .artifacts/explain-qd --collection kb '北京' --top-k 1 --explain-id '"7"'
ragwrench bm25 search --path .artifacts/explain-qd --collection kb '北京' --explain-id '"other"'
```

`--explain-id JSON_ID` implies `--explain` and adds `selected_document` with the
same `id`, `score`, `text`, `metadata` and `explanation` fields as an explained
hit. `results` retains the original top-k ranking; the selected document is
reported separately without a rank, even if it also occurs in `results`.
For this fixture, top-k 1 still contains integer `7` (score about `0.598186`),
while selecting string `"7"` reports its lower score of about `0.420817`.
Selecting `"other"` reports score `0`, document tokens `["atlas"]`, and zero
TF/contribution with empty `document_terms` for the query's `北京` dimension.
The score comes from a Qdrant point-ID-filtered query using the **whole live
corpus's IDF**, independent of top-k. Nonmatching and empty/stopword-only queries
give a selected score of `0`; empty queries retain their warning and have no
query dimensions. Hash collisions can still produce a positive score and show
the actual contributing document terms.

The option accepts one JSON scalar ID using the same string/uint64 rules as
indexing. Unquoted nonnumeric names, malformed JSON, null, booleans, floats,
arrays/objects, empty/oversized strings and out-of-range integers fail with exit
2 and no JSON. Unknown IDs (including deleted or skipped empty documents) also
fail rather than being treated as zero-score documents. Config and collection
checks are unchanged; selection never writes the store or needs a rebuild.

This read-only option scans all live sparse vectors in pages, including
nonreturned documents, so top-k does not change IDF. It retains statistics only
for queried dimensions and vectors only for returned hits and the optional
selected document. It is intended for
the bounded local corpus, with one writer and no concurrent mutation. No extra
index format or rebuild is needed, including for pre-update collections.
Empty/stopword-only queries warn and return an explained object with empty
tokens, dimensions and results; no-match queries retain their token/IDF details
with empty results. Config mismatches, incomplete collections and missing stored
BM25 vectors fail (CLI exit 2, no JSON output). The option never writes the store.

## Incremental add/delete

Update an existing collection using its saved tokenizer, normalized stopwords,
versions, `k1`, `b` and average-length policy. No config flags or stopword file
are needed. This example deletes `a`, adds `c`, then compares with a full rebuild:

```sh
ragwrench bm25 index --path .artifacts/update-qd --collection kb examples/bm25/incremental-initial.jsonl
ragwrench bm25 update --path .artifacts/update-qd --collection kb --add examples/bm25/incremental-add.jsonl --delete-ids examples/bm25/incremental-delete.json
ragwrench bm25 index --path .artifacts/update-qd --collection rebuilt examples/bm25/incremental-final.jsonl
ragwrench bm25 search --path .artifacts/update-qd --collection kb '数据库 备份' > .artifacts/updated-hits.json
ragwrench bm25 search --path .artifacts/update-qd --collection rebuilt '数据库 备份' > .artifacts/rebuilt-hits.json
diff .artifacts/updated-hits.json .artifacts/rebuilt-hits.json
```

The initial input is `a: "数据库 数据库"`, `b: "数据库 备份"`; the addition is
`c: "数据库 快照 恢复 备份"`. Expected: `indexed: 2`, `added: 1`, `deleted: 1`,
`corpus.total_tokens: 8`, `encoder.avgdl: 4`, and identical search results ordered
`b`, `c`. The fixtures are local synthetic data, using pinned qdrant-client 1.20.0.

`--add` takes the same validated JSONL as `index`; `--delete-ids` takes a UTF-8
JSON array of source IDs (up to 10,000 entries and 4 MiB). Either option can be
used alone. Integer `7` and string `"7"` are distinct. An addition's ID must be new;
delete and add the same ID in one batch to replace its text/metadata. Unknown
deletions, duplicate IDs, invalid input and incompatible tokenizer versions fail
before writes (CLI exit 2). Empty additions are skipped; their IDs are not stored.
Deleting all live documents leaves a searchable empty collection (`[]`), with
automatic `avgdl=1` until a later nonempty addition.

Builds now save `corpus.schema`, `avgdl_mode` (`auto` or `fixed`) and post-stopword
`total_tokens` alongside the live `indexed` count. Automatic `avgdl` is recomputed
from the resulting nonempty corpus; explicitly supplied `--avgdl` stays fixed.
Updates scan and encode the live corpus to refresh statistics and collision
metadata. When `avgdl` changes, all retained TF vectors must be rewritten; otherwise
only additions are upserted. Qdrant's IDF modifier maintains live `N` and dimension
document frequencies. There is no performance claim or sublinear-update guarantee.
The report's `skipped` count describes the latest input batch, not deleted history.

Use one writer per local collection. Updates are **not transactional**: validation
and encoding finish before writes, then a persisted `updating` marker blocks
search and further updates until all point operations and metadata finalization
succeed. New builds and updates save an intended-corpus snapshot before point
writes; use `recover` after interruption (below). Older collections without
corpus-policy metadata remain searchable but require one full rebuild before updates, because
their original automatic versus explicitly fixed `avgdl` cannot be inferred.

## Verify one supplied source document

```sh
# Save exactly one strict JSON object (pretty-printed JSON is also accepted):
printf '%s\n' '{"id":7,"text":"数据库 备份","metadata":{"topic":"backup"}}' > .artifacts/document.json
ragwrench bm25 index --path .artifacts/verify-qd --collection kb .artifacts/document.json
ragwrench bm25 verify-document --path .artifacts/verify-qd --collection kb .artifacts/document.json
```

`verify-document` requires a ready local collection and one UTF-8 JSON document
file (maximum 4 MiB, **not JSONL**). It accepts the existing `id`/`text`/optional
`metadata` schema and bounds, with strict duplicate-key/nonfinite-number/unknown-
field rejection. Input is validated before opening storage. No encoder overrides
are accepted: tokenizer, stopwords, versions, hash, `k1`, `b` and `avgdl` come
from the saved config. The example returns this JSON and exits 0:

```json
{"schema":1,"collection":"kb","id":7,"point_present":true,"payload":{"source_id":true,"text":true,"metadata":true,"matches":true},"sparse_vector":{"indices_match":true,"values_match":true,"matches":true},"matches":true,"mismatches":[]}
```

Only the deterministic point for the supplied typed ID is retrieved; integer
`7` differs from string `"7"`. Supported payload fields `source_id`, raw `text`
and `metadata` are compared to the supplied document. Omitted input metadata
means `{}`; a missing stored field is a mismatch. Object key order is ignored;
canonical JSON comparison preserves numeric representations/types (`true`, `1`
and `1.0` differ). Extra stored payload fields are outside this comparison.
The expected TF sparse vector is encoded using the **saved** average length;
no global statistics are recomputed from this sample. Indices compare as sets;
`values_match` compares the complete index-to-weight map. Array order is ignored,
but weights compare exactly without tolerance: pinned local Qdrant 1.20.0 retains
sparse weights across persistence, independently of float32 search scores.

Any valid disagreement returns the same JSON shape with `matches:false` and
**exit 1**. Ordered mismatch categories are `source_id`, `text`, `metadata`,
`sparse_indices`, `sparse_values` as applicable. A missing selected point returns
`point_present:false`, `payload:null`, `sparse_vector:null`, and
`mismatches:["point_missing"]`, also exit 1. Absence is a mismatch even for an
empty/stopword-only document that indexing would skip. An index change also
makes the complete weight map disagree, so both sparse categories are reported.

Invalid input, missing/foreign/malformed storage, pending building/updating,
managed point-count disagreement, or missing/malformed selected `bm25` vector
fail with **exit 2 and no JSON**. Normal readiness/config/aggregate validation
runs before point retrieval. The command refuses to claim vector agreement when
storage cannot establish it. The report discloses no text, tokens, metadata
values, stopwords or vector arrays; encoding warnings that could expose tokens
are suppressed. It reports the caller-supplied ID and comparison booleans only.

This is a read-only comparison with one caller-supplied document. It can detect
same-count external edits to that point which aggregate `status --require-ready`
misses. It does not authenticate the document, prove whole-corpus integrity,
audit saved statistics against the corpus, repair anything or add points.
Unselected points are not inspected. Use a trusted local store, the existing
exclusive client lock and no concurrent mutations; there is no snapshot or
OS-enforced read-only guarantee. Optional jieba may use its usual dictionary cache.

## Verify a supplied source batch

```sh
ragwrench bm25 index --path .artifacts/verify-batch-qd --collection kb examples/bm25/explain-corpus.jsonl
ragwrench bm25 verify-documents --path .artifacts/verify-batch-qd --collection kb examples/bm25/explain-corpus.jsonl
```

`verify-documents` accepts a nonempty strict UTF-8 JSONL file using the existing
source schema. Blank lines are ignored. The entire file is validated **before
opening storage**: at most 10,000 documents, 64 MiB total including blank lines,
4 MiB per physical line, and 1,000,000 characters per text. Duplicate typed IDs,
duplicate JSON keys (including nested objects), nonfinite numbers, unknown fields
and invalid records are rejected. Integer `7` and string `"7"` are distinct.
No encoder override flags are accepted.

Default verification accepts subsets. To require a supplied record for every
saved indexed document by count, opt in:

```sh
ragwrench bm25 verify-documents --path .artifacts/verify-batch-qd --collection kb \
  --require-complete examples/bm25/explain-corpus.jsonl
```

After full input validation and the ordinary saved readiness/config/count/aggregate
checks, `--require-complete` requires the unique supplied record count to equal
the validated saved indexed `document_count`. Fewer or more records cause
**exit 2 with no JSON**, before encoding or retrieving any selected points;
stderr includes `document count mismatch: expected=N actual=M`, where `expected`
is the saved indexed count and `actual` is the supplied count. Integer `7` and
string `"7"` count separately. Agreement leaves the JSON and exit 0/1 semantics
unchanged. Missing points in an equal-count batch remain valid mismatches.

Empty JSONL files/lists remain invalid, even for a ready collection with zero
indexed documents after deletion. Any valid nonempty batch fails the count gate
against that collection (`expected=0`). The count describes indexed documents,
so omit originals skipped for empty/stopword-only text when using the gate.
Count agreement alone does not establish ID membership or source authentication,
audit global statistics against corpus contents, or guarantee snapshot integrity.

The command validates saved readiness/config/count/aggregate statistics once,
reuses one encoder with the saved `avgdl`, and retrieves only the supplied points.
Each entry in `results` has exactly the `verify-document` schema and comparison
semantics above, in **input order**. The top-level object is:

```json
{"schema":1,"collection":"kb","matches":true,"totals":{"documents":3,"matched":3,"mismatched":0,"missing":0},"mismatch_counts":{"point_missing":0,"source_id":0,"text":0,"metadata":0,"sparse_indices":0,"sparse_values":0},"results":["per-document summaries as shown above"]}
```

Here `results` is an array of summary objects, not strings. `totals.mismatched`
counts documents with any disagreement; `totals.missing` counts missing selected
points and is a subset of mismatched documents. Each `mismatch_counts` value
counts documents with that category; one document may have multiple categories.
`matches` is true exactly when all supplied documents agree. Exit **0** means
agreement; exit **1** returns the complete JSON with at least one valid mismatch.

The batch is **all or error**: invalid input/storage, a pending collection,
count/config/aggregate disagreement, or any unavailable/malformed selected vector
aborts the entire batch with **exit 2 and no JSON**, even after earlier valid
matches or mismatches. The API raises instead of returning partial results.
A missing selected point is still a valid mismatch if collection readiness passes.

Reports omit text, metadata values, tokens, saved config and vector arrays.
There is no corpus scan, global-statistic recomputation, repair, addition,
authentication or whole-corpus integrity claim. Unselected point damage is
outside the comparison. Normal local-client storage reads and exclusive locking
still apply; no concurrent-mutation or OS-enforced read-only guarantee is made.

## Export selected stored documents

```sh
# For a ready collection containing integer 7 and string "7":
printf '["7", 7]\n' > .artifacts/export-ids.json
ragwrench bm25 export-documents --path .artifacts/qd --collection kb \
  --ids .artifacts/export-ids.json --output .artifacts/selected.jsonl
# stdout: {"schema": 1, "collection": "kb", "exported": 2}
# The output must be fresh. Reindex into a new collection:
ragwrench bm25 index --path .artifacts/qd --collection selected .artifacts/selected.jsonl
```

`--ids` is a strict UTF-8 JSON array of exact source IDs, limited to 4 MiB and
1–10,000 unique IDs. Integer `7` and string `"7"` select different points;
duplicates, invalid ID types/ranges and unknown IDs are errors. An empty selection
is an error because the index input schema requires a nonempty corpus.
Export retrieves only the selected points, in requested order, using the saved
ready config/count/aggregate validation once. It does not compare caller-supplied
content, encode text, read vectors, scan the corpus or change points/config.

The file is UTF-8 JSONL in the existing index input schema, containing only
`id`, original stored `text` and `metadata`. Unicode is preserved without text
normalization; nested JSON types remain distinct, including integers, floats,
booleans and null. JSON whitespace/key order need not match the original input.
Every exported record has a `metadata` object: omitted input metadata was stored
as `{}`, and absent stored metadata also normalizes to `{}`. Omitted-versus-empty
metadata provenance cannot be reconstructed. Extra stored payload fields,
vectors, collection config and statistics are excluded. Malformed supported
source fields or a source ID inconsistent with its point identity are errors.

Export is all-or-error: it validates every selected record and serialized size
before publishing any output. Existing limits apply, including 1,000,000 text
characters, 4 MiB per JSONL line and 64 MiB total, counting UTF-8 bytes and
newlines. Success exits 0 with the export count above; any input, readiness,
selected-record or output error exits 2 with stderr diagnostics and no JSON.
A missing/invalid later record leaves no output or temporary file.

The output parent directory must already exist. The destination must be fresh,
distinct from the selection input, and outside the storage directory, including
resolved symlink aliases. Existing files, directories, hard links and symlinks
(including dangling ones) are refused without replacement. Publication uses a
same-directory mode-0600 temporary file and an atomic hard link that also refuses
a destination created after validation. Ordinary write/publication failures
clean up the temporary file; the filesystem must support hard links. This is
atomic publication, with no power-loss durability guarantee; an abrupt process
crash can leave an orphan temporary file.

This exports selected **stored indexed records**, not a complete backup or
an authenticated original corpus. Empty/stopword-only sources skipped during
index/update have no retained points and cannot be recovered by their IDs.
Unselected records are not audited. Reindexing a subset recomputes its corpus
statistics and IDF, so matching selected sources does not imply whole-collection
score parity. Use trusted local paths/storage and one writer; no concurrent
mutation or snapshot guarantee is provided. Qdrant still takes its usual exclusive lock.

## Reindex with a saved encoder config

`index --encoder-config FILE` accepts a caller-saved **Encoder.config object**,
for example the `config` field from `status`. It reuses the exact compatible
tokenizer, normalized stopwords, `k1`, `b` and `avgdl` in a fresh collection.
The usual index JSON manifest is returned, with `encoder` equal to the supplied
config and `corpus.avgdl_mode: "fixed"`. This example uses the bundled typed-ID
corpus and exports only the two selected records:

```sh
ragwrench bm25 index --path .artifacts/config-original --collection kb \
  examples/bm25/explain-corpus.jsonl --tokenizer whitespace --k1 1.8 --b 0.3
ragwrench bm25 status --path .artifacts/config-original --collection kb > .artifacts/status.json
# Save only the config object, not the whole status wrapper:
python3 -c 'import json; d=json.load(open(".artifacts/status.json")); print(json.dumps(d["config"], ensure_ascii=False))' > .artifacts/encoder.json
printf '["7", 7]\n' > .artifacts/config-ids.json
ragwrench bm25 export-documents --path .artifacts/config-original --collection kb \
  --ids .artifacts/config-ids.json --output .artifacts/config-selected.jsonl
ragwrench bm25 index --path .artifacts/config-copy --collection selected \
  --encoder-config .artifacts/encoder.json .artifacts/config-selected.jsonl
```

The supplied `avgdl` is **fixed**, even if the original collection computed it
automatically. It is not recomputed from this input or subsequent updates.
Token totals and collection IDF still describe the new selected corpus; preserving
config and source records does not establish full-collection score parity,
source authenticity or a complete backup. The index command reads only the
provided files and destination store; it needs no original collection access.

The config file is strict UTF-8 JSON, at most **1 MiB** (including whitespace),
with exactly the fields produced by `Encoder.config`. Whole status/build wrappers,
extra/missing fields, duplicate keys, nonfinite or overflowing numbers, malformed
Unicode and incompatible tokenizer/hash/Unicode/jieba versions are errors.
`Encoder.from_config` validates runtime compatibility; stopwords must already be
in the saved normalized, sorted, unique list form. Optional jieba still requires
its installed extra. No fields are inferred, repaired or exported automatically.

Any combination with individual index `--tokenizer`, `--stopwords`, `--k1`, `--b`
or `--avgdl` flags is rejected, including equal values. Config conflicts,
validation and existing JSONL input limits are checked before opening storage.
Errors exit 2 with stderr diagnostics and no JSON. Existing collections are
refused without replacement. Without `--encoder-config`, index retains its
normal defaults and automatic average-length behavior (or explicit `--avgdl`).

## Check collection status

```sh
ragwrench bm25 status --path .artifacts/update-qd --collection kb
# Opt-in shell gate:
ragwrench bm25 status --path .artifacts/update-qd --collection kb --require-ready
# Require the two intended documents from the update example:
ragwrench bm25 status --path .artifacts/update-qd --collection kb --require-ready --expect-documents 2
```

`status` accepts an existing local path and collection name, plus optional
`--require-ready` and `--expect-documents N`, with no config or stopword-file
overrides. It writes a schema-1 JSON object to stdout:

```json
{"schema": 1, "collection": "kb", "state": "ready", "config": {"schema": 1, "tokenizer": "cjk-bigram", "tokenizer_version": 1, "unicode_version": "14.0.0", "jieba_version": null, "hash": "sha256-first32-big-endian-v1", "stopwords": [], "k1": 1.2, "b": 0.75, "avgdl": 4.0}, "corpus": {"document_count": 2, "avgdl_mode": "auto", "total_tokens": 8}, "points": {"current": 2}, "recovery_snapshot_present": false}
```

This is the incremental fixture after a successful update. `state` is `ready`,
`building` or `updating`; by default all three valid states exit 0. With
`--require-ready`, a ready collection emits exactly the same JSON and exits 0;
a valid pending collection exits 2 with no stdout and one of these stderr lines:

```text
ragwrench bm25: error: collection is not ready: state=building
ragwrench bm25: error: collection is not ready: state=updating
```

The gate runs **after** the same status validation, so malformed or missing
storage keeps its existing diagnostic instead of being reported as merely
pending. It does not require a valid recovery snapshot.
`points.current` is the live point count. `config` and `corpus`
are saved aggregates: for an incomplete operation they describe its **intended**
corpus, and live points can differ from `corpus.document_count`. Ready status
reuses the normal saved-config/runtime and managed point-count checks; all
states use the same saved aggregate checks as ready recovery. Absent legacy
corpus-policy metadata yields null `avgdl_mode` and `total_tokens`; a present
malformed corpus field is rejected. Missing paths/collections, foreign
collections, invalid state/config/count/corpus manifests and incompatible encoder
versions exit 2 with stderr diagnostics and no JSON. A missing path is not created.
Saved encoder `schema` and `tokenizer_version` must be JSON integers: `true` and
`1.0` are malformed even though Python compares them equal to `1`. This check
applies in every state and to all commands that load the saved encoder config.

`--expect-documents N` requires `corpus.document_count` to equal a nonnegative
integer N. Agreement emits exactly the ordinary schema-1 JSON and exits 0;
disagreement exits 2 with no JSON and a diagnostic such as:

```text
ragwrench bm25: error: document count mismatch: expected=3 actual=2
```

Negative or noninteger arguments fail before opening storage. Zero is valid;
there is no upper bound on the expected count (an unattainable count simply
mismatches). Normal storage/config/aggregate validation runs first, followed by
`--require-ready` if present, then the count comparison. Thus a pending state
with both gates fails readiness even if its count also disagrees; malformed or
missing storage keeps its ordinary diagnostic. For pending operations the saved
count is the **intended** number of nonempty indexed documents, not the number of
live points already written. Skipped empty/stopword-only inputs do not count.
Count agreement is not a source-integrity or recovery guarantee.

`recovery_snapshot_present` reports whether the manifest contains a `recovery`
key. It does **not** validate that value: missing, null or corrupt snapshots do
not prevent reporting an otherwise valid pending manifest. Use `recover
--dry-run` to validate the full snapshot/checksum/encoding and count replay work.
Status does not inspect snapshot contents, scan points, tokenize documents or
estimate recovery operations. It does not audit omitted diagnostic fields such
as collision vocabulary or the latest skipped-input count. No document text,
source IDs, payload metadata, vectors or collision vocabulary appear in output;
saved config still contains literal stopwords.

Status performs no mutations or fsync and preserves files and search results.
It opens the existing local store with Qdrant's normal exclusive lock; use one
writer and readable storage. This is not an OS-enforced read-only filesystem mode
or a content audit: same-count external document/vector edits may evade detection.

## Recover an interrupted build or update

```sh
# After an interrupted index/update, with no original input files needed:
ragwrench bm25 recover --path .artifacts/update-qd --collection kb
ragwrench bm25 search --path .artifacts/update-qd --collection kb '数据库 备份'
```

For the incremental example above, interruption after the update checkpoint
still recovers the intended documents `b` and `c`: `indexed: 2`,
`corpus.total_tokens: 8`, `encoder.avgdl: 4`, and the same results as `rebuilt`.
`recover` takes only an existing local path and collection name. It writes the
ready manifest plus `recovered: true` as JSON to stdout. Running it on an already
ready managed collection is a read-only success with `recovered: false`.
Neither report contains the snapshot's documents; original add/delete counts
are not repeated. Search and further updates work normally after success.

Inspect recovery without replaying it:

```sh
ragwrench bm25 recover --path .artifacts/update-qd --collection kb --dry-run
```

`--dry-run` writes a separate schema-1 JSON summary, for example an update
interrupted before deleting `a` or writing `c` in the incremental fixture:

```json
{"schema": 1, "collection": "kb", "dry_run": true, "state": "updating", "pending": true, "config": {"schema": 1, "tokenizer": "cjk-bigram", "tokenizer_version": 1, "unicode_version": "14.0.0", "jieba_version": null, "hash": "sha256-first32-big-endian-v1", "stopwords": [], "k1": 1.2, "b": 0.75, "avgdl": 4.0}, "corpus": {"document_count": 2, "avgdl_mode": "auto", "total_tokens": 8}, "points": {"current": 2, "remove": 1, "rewrite": 2}}
```

`state` is the current `building`, `updating` or `ready` marker; `pending` is
false only for `ready`. `config` and `corpus` describe the intended ready corpus,
not partial live data. `points.current` counts live points, `remove` counts live
IDs absent from the intended corpus, and `rewrite` counts **all target upserts**,
including missing points, replacements and already-correct retained vectors.
These are the next recovery's operation counts, not a content diff or the
original update's add/delete counts. Delete-all can have zero rewrites; a ready
no-op always has zero removals and rewrites. No source IDs, document text,
metadata, vectors or collision vocabulary appear in this summary. Saved config
still includes literal stopwords. The ordinary recovery report is unchanged.

Inspection uses the same full pending-snapshot checksum, schema, runtime/config,
statistics, collision and encoding validation as replay. Invalid snapshots exit
2 with diagnostics on stderr and no JSON, before any writes. Ready collections
use the normal config and point-count checks without retokenizing their corpus.
Both inspection and ordinary ready no-op recovery also validate saved corpus
statistics: integer schema/counts (booleans and floats are rejected), supported
average-length policy, at least one token per indexed document, zero tokens for
an empty corpus, and agreement between automatic `avgdl` and saved totals.
Fixed `avgdl` remains independent of the token average. Malformed statistics,
including a non-object/null corpus field or overflowing automatic average, fail
with exit 2 and no JSON. Legacy ready collections with **no** corpus field still
report `null` for `avgdl_mode` and `total_tokens`.
These checks validate saved aggregates, not their agreement with document text;
ready inspection does not scan live documents or detect same-count external edits.
Inspection does not call collection creation,
deletion, upsert, metadata update or fsync, and preserves managed store contents
and search results. It still opens the existing local store through Qdrant and
holds its normal exclusive lock; it is not a mode for concurrent writers or
unreadable/corrupt storage. Pending inspection encodes the entire bounded snapshot
and scans live IDs in pages; it has the same in-memory limits as replay.

Before any point writes, builds and updates store a versioned intended-corpus
snapshot inside collection metadata: complete nonempty source documents, typed
IDs, text/metadata, the target encoder/corpus/collision manifest, collection name
and a SHA-256 integrity checksum. For local disk clients, metadata and its parent
directory are fsynced after Qdrant's atomic metadata replacement. The snapshot
is capped at 128 MiB of serialized JSON, in addition to the existing input/live
corpus limits, and is held in memory. It temporarily duplicates corpus text in
metadata; it adds no points and does not affect IDF. In-memory Python clients
support replay during their lifetime but have no restart durability.

Recovery validates the entire snapshot and runtime configuration before point
writes. It deletes obsolete points and rewrites all intended vectors in batches,
including retained vectors affected by automatic average length. It restarts
from the snapshot on every retry, so interruption during recovery itself is
safe to retry. Finalization replaces the pending marker and snapshot together
with the ready manifest. Until then, search and update refuse the collection.
There is no rollback to the previous corpus, progress cursor or automatic retry.
Use one writer and allow the local client to hold its store lock throughout.

Missing paths/collections, foreign collections, missing/corrupt snapshots,
unsupported snapshot schemas, inconsistent statistics and incompatible saved
encoder versions fail (exit 2, diagnostic on stderr, no JSON or point writes).
A checksum detects accidental changes, not malicious edits to trusted storage.
Ready collections still undergo the normal config and point-count checks.
Interrupted collections from older versions without a snapshot require a full
rebuild into a new collection; their intended contents cannot be inferred from
partial points. Recovery also requires a readable Qdrant store and metadata:
it is not a backup or a repair tool for filesystem/database corruption. Tests
exercise abrupt process exit, partial point batches, and both sides of metadata
finalization on Linux; they do not simulate power loss or storage hardware faults.

## Tokenizers and stopwords

All modes apply Unicode NFKC normalization and lowercase (not case folding).

| Mode | Behavior |
| --- | --- |
| `whitespace` | Baseline: split on whitespace, retaining punctuation inside tokens. |
| `unicode` | Unicode letter/number runs with combining marks; punctuation splits runs. CJK sentences can remain one long token. |
| `cjk-bigram` (default) | Overlapping pairs over contiguous Han/Kana/Hangul runs; isolated CJK characters are unigrams. Latin/digit runs remain words. Punctuation, whitespace and Latin/CJK transitions separate runs. |
| `jieba` (extra) | Fixed jieba bundled dictionary, HMM disabled; punctuation-only tokens discarded. Intended primarily for Chinese. |

For example `Qdrant向量数据库` becomes
`["qdrant", "向量", "量数", "数据", "据库"]` in the default mode.
Kanji and kana are one contiguous CJK run, so a pair may cross their boundary.

```sh
pip install 'ragwrench[qdrant,jieba]'
# Optional jieba builds a standard dictionary cache; control its location:
mkdir -p .artifacts/tmp
TMPDIR="$PWD/.artifacts/tmp" ragwrench bm25 encode '我来到北京清华大学' --tokenizer jieba
printf 'qdrant\n数据\n' > .artifacts/stopwords.txt
ragwrench bm25 index --path .artifacts/qd --collection filtered examples/bm25/corpus_zh.jsonl --stopwords .artifacts/stopwords.txt
```

Stopwords are literal **emitted tokens**, one per line; blank lines are ignored.
Entries are NFKC/lowercased, deduplicated, and stored in collection metadata.
They are not phrases, patterns, scripts or automatically segmented words.
The file is limited to 1 MiB. No file is needed when searching: saved contents
are automatically reused. Requesting jieba without its extra gives an explicit
installation error.

## Encoding and Qdrant mapping

For token frequency `tf`, post-stopword document length `dl`, and average length
`avgdl`, each document dimension has weight:

```text
TF = tf * (k1 + 1) / (tf + k1 * (1 - b + b * dl / avgdl))
IDF = ln(1 + (N - df + 0.5) / (df + 0.5))
score = sum(query_dimension * TF * IDF)
```

Defaults are `k1=1.2`, `b=0.75`. Indexing computes `avgdl` from nonempty tokenized
documents, unless `--avgdl` is supplied. CLI `encode` and the Python API default
to `avgdl=100`: supply your corpus's average for meaningful document weights.
`k1` and `avgdl` must be positive finite numbers; `b` must lie in [0,1]. Extreme
parameters producing invalid/underflowed weights are rejected.

Each unique query token contributes **1.0**, irrespective of repetition. We store
TF-side weights in the named sparse vector `bm25`, enable `Modifier.IDF`, and
call `query_points`. Qdrant supplies collection IDF once; we never preapply IDF.
Empty/stopword-only documents are warned about and skipped, so they contribute
neither to `avgdl` nor to `N`. An all-empty build input creates no collection and
returns `created: false`. An empty query warns and returns `[]`.

A token's index is the **first four bytes of SHA-256(UTF-8(token)), unsigned,
big endian**. There is no Python `hash()` dependence. Hash collisions merge TF
weights at that index; the query dimension stays 1.0. Observed collisions warn
and appear in `collision_stats` (including colliding tokens), saved with the
collection. This is a 32-bit approximation: collisions can cause false matches.
Search checks collisions within its query; it does not persist the whole corpus
vocabulary to detect a previously unseen query token colliding with one corpus
token. For collision-sensitive workloads use a vocabulary-based index instead.

The collection itself stores the full encoder config: tokenizer/version, Unicode
data version, jieba version when applicable, hash version, stopword contents,
`k1`, `b`, and `avgdl`. Query overrides such as `--tokenizer unicode` or `--k1 2`
are accepted only when they exactly match the stored config. Runtime version
mismatches require rebuilding. A caller-saved config file can seed a fresh index
or offline encode; no synthetic metadata point alters Qdrant's IDF statistics.
Interrupted builds remain marked `building` and updates remain marked `updating`;
both are refused at search time.

## Python API

```python
from ragwrench.bm25 import Encoder
from qdrant_client import models

encoder = Encoder(tokenizer="cjk-bigram", k1=1.2, b=0.75, avgdl=12)
documents = encoder.encode_documents(["向量数据库支持备份", "数据库快照恢复"])
query = encoder.encode_query("数据库 备份")
qdrant_vector = models.SparseVector(**documents[0].as_dict())
print(query.indices, query.values, encoder.collision_stats)
```

`encode_documents` returns one vector per input (empty entries retain their
position as empty vectors). Encoders accumulate collision observations across
calls. `Encoder.from_config(encoder.config)` reconstructs a compatible encoder.
Saved `schema` and `tokenizer_version` require exact integer types; malformed
versions raise `ValueError`. BM25 `k1`, `b` and `avgdl` still accept finite
integers or floats within their documented ranges.
`ragwrench.bm25.store` exposes `build_collection`, `update_collection`, `recover_collection`,
`status_collection`, `verify_document`, `verify_documents`, `export_documents`, `load_encoder`,
`search_collection` and `explain_collection`
for callers already managing a
Qdrant client; the CLI only opens local paths.
`status_collection(client, "kb")` returns the status summary without validating
a recovery snapshot. Its keyword-only `require_ready=True` option returns the
same ready summary, but raises `ValueError("collection is not ready: state=building")`
or the corresponding `state=updating` error for a valid pending collection,
after normal status validation. Default `require_ready=False` returns every
valid state. Keyword-only `expect_documents=None` disables the count guard;
`expect_documents=N` requires an exact nonnegative Python `int` (booleans,
floats and strings are rejected with `ValueError` before any client access).
After normal validation and the readiness gate, disagreement raises
`ValueError("document count mismatch: expected=3 actual=2")`; agreement returns
the unchanged summary. It compares the saved intended count, including in
pending states, and accepts zero and counts above the storage limit. These
options never scan points, validate snapshots, mutate or fsync.
`verify_document(client, "kb", {"id": 7, "text": "数据库 备份"})` returns the
same verification report; a mismatch returns `matches=False` (no exception),
while invalid input/storage or unavailable comparisons raise `ValueError`.
`read_document(path)` reads the strict single-document JSON input.
`recover_collection(client, "kb", dry_run=True)` returns
the full recovery inspection summary.
For example, `update_collection(client, "kb", additions=[{"id": "new", "text":
"数据库备份"}], delete_ids=["old"])` performs one batch with the saved config.
`explain_collection(client, "kb", "数据库 备份", top_k=3)` returns the same
explanation object as `search --explain`, accepting the same config overrides
as `search_collection`.
Pass `source_id=7` or `source_id="7"` to add `selected_document`, including
nonmatches and documents outside top-k. The default `source_id=None` disables
selection. Invalid or unknown IDs raise `ValueError`.
`recover_collection(client, "kb")` explicitly replays an interrupted operation
from its saved snapshot, or reports a ready collection without writing.
Keep one matching config and IDF-enabled sparse collection when using vectors
with your own client. These hashes **do not match FastEmbed/native BM25 hashes**.

`verify_documents(client, "kb", documents, *, require_complete=False)` accepts a
nonempty bounded list of source dictionaries and returns the complete batch
summary above, or raises on any input/storage failure. All input records and duplicate IDs are validated
before any client access. File byte/line limits belong to `read_corpus(path)`;
the API follows ingestion's existing list validation and text/document limits.
The keyword-only gate requires an exact boolean, rejected before client access
otherwise. With `True`, a supplied-count mismatch raises `ValueError` after normal
saved validation and before selected comparisons, using the same expected/actual
diagnostic as the CLI. `False` preserves subset verification.
Both verification functions leave caller objects unchanged.

`export_documents(client, "kb", ["7", 7])` returns a complete list of source
dictionaries in that order, or raises if selection, readiness, selected payloads
or serialized JSONL bounds fail. Selection validation happens before client
access. It leaves caller objects unchanged and performs no file publication;
`read_export_ids(path)` reads the bounded strict nonempty selection. The CLI
publishes the file and returns the count.

## Reproduce tests and tokenizer comparison

```sh
pip install -e '.[qdrant,jieba,test]'   # from a clone of the repository
python -m pytest tests/bm25 -q
ragwrench bm25 eval
# JSON report defaults to .artifacts/eval.json, or choose a destination:
ragwrench bm25 eval --output examples/bm25/eval-results.json
ragwrench bm25 eval --include-jieba --output .artifacts/eval-jieba.json
```

Tests are offline and single-process; pytest temporary files stay under
`.artifacts/`. Without the optional extra, its real-dictionary and incremental
update tests are skipped; the missing-dependency error is always tested. The fixtures in
`src/ragwrench/bm25/data/` contain 12 original, redistributable synthetic zh/ja/mixed
(including Korean) documents and 9 explicitly judged queries. Evaluation runs
**actual Qdrant retrieval** for whitespace, Unicode and CJK bigram tokenizers,
checks match sets and scores against independent token-space Python BM25, and
writes per-query rankings plus macro recall@k/MRR overall and per language.
Repeated runs are deterministic. Evaluation fetches all fixture matches before
truncating, resolving ties by source-ID order.

The committed `examples/bm25/eval-results.json` is generated by the command above:

| Tokenizer | Overall recall@3 | Overall MRR | Chinese recall@3 |
| --- | ---: | ---: | ---: |
| whitespace | 0.2222 | 0.2222 | 0.0000 |
| unicode | 0.2222 | 0.2222 | 0.0000 |
| cjk-bigram | 1.0000 | 1.0000 | 1.0000 |

These deliberately small substring-query fixtures demonstrate the failure of
whitespace segmentation, **not** general relevance superiority or a performance
benchmark. Score parity is checked within 1e-5 absolute error.

## Scope and operational limits

- Local-mode builds and incremental add/delete only: no overwrite, remote URLs,
  server deployment, dense/learned embeddings or language detection. A new
  collection is required to change tokenizer/parameters or rebuild legacy
  interrupted writes without an intended-corpus snapshot.
- Local-mode scope: at most 10,000 records, 64 MiB JSONL, 4 MiB per line,
  1,000,000 characters per text and search top-k in [1,1000]. Corpus and vectors
  are held in memory; these are input caps, not a memory-use guarantee. One
  process may hold a local store lock at a time; clients are always closed.
- Storage is a trusted local Qdrant directory. Collection names are restricted
  to 1–64 ASCII letters/digits/underscore/hyphen, starting alphanumeric, so they
  cannot traverse paths. No expressions or external workflow steps are executed.
  `recover --dry-run` inspects recovery without replaying writes. Only explicit
  database/report destinations are written by mutating commands; optional jieba
  may also use its standard temporary dictionary cache.
- Collections without the `bm25` sparse IDF vector, ready metadata or compatible
  config are refused. Point count changes are detected; aggregate status/search
  validation can miss same-count external payload/vector edits. `verify-document`
  compares one supplied source with its selected point, not the entire corpus.
  Do not mutate a managed collection externally.
- Bigrams are not linguistic segmentation. Single-character queries match only
  isolated-character tokens; no single-character substring fallback, stemming,
  fuzzy matching or relevance tuning. Cutoff ties in ordinary search are chosen
  by Qdrant, then sorted by source ID within the returned tie set.
